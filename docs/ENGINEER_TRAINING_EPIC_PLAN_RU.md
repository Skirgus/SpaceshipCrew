Документ фиксирует **конечный результат**, сценарий по GDD и декомпозицию на мелкие подзадачи с готовыми промптами для отдельных агентов.

## 0. Целевой пайплайн контента (актуализация)

Ожидаемый результат строится на **кастомных мешах**, не на greybox-примитивах:

1. **Blender MCP** — модули отсека корабля + модели станций/инструментов инженера.
2. **Экспорт FBX** (по скиллу модулей) → импорт в Unreal.
3. **Unreal MCP + Editor** — ModuleDefinition / StaticMesh, сборка уровня из модулей, BP устройств.
4. **C++** — interact, энергосеть, ремонт, scenario director, меню `Тренировки → Инженер`.
5. **Сценарий** на уровне создаёт ситуации → игрок использует станции инженера.

Минимальный набор из Blender: 1–2 interior-модуля; консоль энергосети; горелка; повреждённая панель (± intact); опц. пульт реактора. Конвенции: `docs/SHIP_MODULE_BIG_MODULAR_GUIDE_RU.md`, сетка `docs/SHIP_BUILDER_GRID_RU.md`. Порядок исполнения агента — §5.

## 1. Что должно быть в конце эпика (DoD)

Игрок в PIE / standalone:

1. Главное меню → **Тренировки** → в списке появляется пункт **«Инженер»**.
2. По нажатию загружается тренировочный уровень: персонаж экипажа (3-е лицо) оказывается **внутри корабля из кастомных модулей (Blender → UE)**.
3. Запускается **обучающий сценарий** по обязанностям инженера из `GAME_DESIGN_DOCUMENT.md`:
   - распределение энергии (щиты / оружие / двигатели);
   - реакция на аварийный алерт;
   - базовый ремонт повреждённой панели/узла инструментом («горелка»).
4. На уровне размещены **точки взаимодействия с кастомными мешами устройств**, через которые сценарий проводит игрока.
5. Для точек реализованы **интерфейсы** (энергосеть; прогресс/статус ремонта).
6. Есть **ремонтный инструмент** и хотя бы одна повреждённая панель/модуль-узел, которые можно починить.
7. После выполнения шагов — **успех** и возврат в главное меню (или экран «Тренировка пройдена» → меню).
8. Минимум автотестов на модели энергии и условие завершения сценария; ручной smoke end-to-end.

**Вне эпика (Non-goals):** открытый мир и перелёты хаб↔хаб; кампания/бюджет/найм; пилот/капитан/стрелок; сеть/мультиплеер; полноценный flight sim и бой; высокодетальный интерьер; полный каскад пожаров/отказов.

## 2. Сценарий тренировки (по GDD)

Опора на GDD:

- роль инженера: реактор, энергосеть, ремонт, перегрев;
- таблица действий: мощность/перегрузка, доли энергии, ремонт критичных узлов;
- Feature B1.4: *пресеты энергии, реакция на аварийный алерт, базовый ремонт* → DoD: *система стабилизирована и авария устранена*;
- MVP: *распределение энергии и экстренный ремонт*;
- ремонт панелей: ручной инструмент («горелка»), смена состояния меша/материала.

### Сюжетная рамка (1 экран)

> Учебная авария на учебном корабле: энергосеть разбалансирована, повреждена корпусная панель. Стабилизируй питание и устрани повреждение.

### Шаги (жёсткий порядок для обучения)

| # | Цель | Точка взаимодействия | Действие игрока | Условие шага |

## 4. C++ vs Blueprint vs Unreal MCP

### 4.1 Что даёт текущий `user-unreal-mcp` в этой сессии

Сейчас доступны в основном:

- `AIAssistant.GetProjectContext` / `GetDockedContext` — контекст проекта и **открытого в Editor ассета** (граф, selected nodes);
- inspection Behavior Tree.

**Полноценного API «создай ноду / соедини пины / поставь актор на уровень» в подключённом MCP пока нет.**  
Workflow «я открываю Blueprint → агент правит его через MCP» станет сильным, когда toolset расширят (или поставят rich Unreal-MCP плагин). До этого: агент пишет **C++ Blueprintable-базы + инструкции**, ты создаёшь/открываешь BP в Editor, агент опирается на `GetDockedContext` и подсказывает/правит то, что MCP реально умеет.

### 4.2 Принцип разделения для этого эпика

| Слой | Где | Зачем |
|------|-----|--------|
| Контракты, инварианты, автотесты | **C++** | Энергия (сумма долей), occupy/leave, условие Complete — детерминизм и Automation Tests |
| Travel/роутинг меню | **C++** (как сейчас Slate) | Уже в коде; пункт «Инженер» — расширение |
| Визуал, расстановка, тюнинг, UMG, Level scripting | **Blueprint / UMG / Level** | Быстро итерируется в Editor; удобно открыть ассет и донастроить с агентом |
| Сценарий шагов (порядок, тексты, маркеры) | **BP Director** на C++-каркасе или Level BP | Контент тренировки меняется часто |

**Паттерн:** C++ `UCLASS(Blueprintable/BlueprintType)` + `BlueprintImplementableEvent` / `BlueprintNativeEvent` → дочерний `BP_*` / `WBP_*`. Агент не дублирует геймплей только в Level BP без базы — иначе не протестировать.

### 4.3 Что лучше делать в Blueprint (открой ассет → работай с агентом)

Имеет смысл завести и держать в Content (агент помогает, когда ассет в фокусе Editor):

1. **`BP_CrewCharacter`** (parent: C++ character) — mesh/капсула, spring-arm, mapping context Enhanced Input в редакторе, простые FX.
2. **`BP_EnergyConsole`** (parent: C++ `CrewWorkstation`) — меш консоли, socket occupy, вызов показа `WBP_EnergyConsole`.
3. **`WBP_EnergyConsole`** — ползунки/пресет «Оборона», биндинг к C++ модели энергии.
4. **`BP_DamagedPanel`** — состояния материала Intact/Damaged/Repaired, виджет прогресса ремонта.
5. **`BP_RepairTorch` / pickup** — визуал инструмента, выдача в inventory/equip.
6. **`BP_EngineerTrainingDirector`** — тексты objectives, ссылки на консоль/панель/маркеры на уровне, Timeline подсказок; логика Complete вызывает C++ API или интерфейс.
7. **`WBP_TrainingObjective` / `WBP_TrainingComplete`** — HUD цели и экран успеха.
8. **Карта `EngineerTraining`** — сборка из **Blender-модулей**, PlayerStart, расстановка BP-устройств, lighting; тонкий Level BP → Director.

### 4.4 Что лучше оставить в C++ (не тащить в BP)

1. **`UShipEnergyGrid` / model** — SetShare, clamp, пресеты; **автотесты**.
2. **`ICrewInteractable` + occupy/leave** — один оператор, отказ второму; автотест.
3. **`URepairableState`** или компонент прогресса 0..1 → Repaired; автотест.
4. **Scenario step enum + проверка условий** (щиты ≥ X, панель Repaired) — можно тонкий C++ subsystem; BP только оркестрирует UX.
5. **`SpaceshipCrewLevelTravel` + меню Trainings→Engineer`**.
6. **GameMode/PC** базовые классы (BP children ok).

### 4.5 Как переложить подзадачи E* на гибрид

| ID | C++ | Blueprint / уровень (MCP-friendly) |
|----|-----|-------------------------------------|
| E1 | Character base, Interact trace | `BP_CrewCharacter`, Input Mapping |
| E2 | Workstation occupy API | `BP_EnergyConsole` placeholder mesh |
| E3 | Energy model + тесты | `WBP_EnergyConsole`, пресеты в BP defaults |
| E4 | Repair progress API + тесты | `BP_DamagedPanel`, `BP_RepairTorch` |
| E5 | GameMode base, soft path | **Карта из Blender-модулей + props** |
| E0 (до/параллельно E5) | — | **Blender: модули + консоль + панель + горелка → FBX** |
| E6 | Route + OpenLevel | Опционально WBP списка тренировок |
| E7–E9 | Step conditions API | **`BP_EngineerTrainingDirector`**, objectives WBP |
| E10 | Overload flag на модели | UI тумблер в том же WBP |
| E11 | Статус docs/тесты | Полировка ассетов в Editor |

### 4.6 Практический ритуал с MCP

1. Агент делает C++ базу и компилит модуль.
2. Ты в Editor: Create Blueprint based on… / Open Level.
3. Открываешь нужный `BP_*` / `WBP_*` (чтобы `GetDockedContext` его видел).
4. Агент: MCP context → правки через доступные tools **или** точные инструкции «добавь ноду X / bind Y», если edit API ещё нет.
5. Не собирай весь сценарий только в Level Blueprint — Director как BP-актор на уровне проще переиспользовать и открывать для MCP.

## 5. Порядок работ агента (что буду делать по шагам)

Ниже — фактический план исполнения под ожидание «модули и устройства из Blender, уровень, меню, ситуации».

### Фаза A — Контент в Blender (`user-blender`)

1. Проверить addon (`get_addon_status`), сцену; зафиксировать масштаб (1 uu = 1 cm UE, модуль по сетке проекта).
2. Собрать **модуль коридора/отсека** с интерьером (пол/стены/потолок), pivot/сокеты по гайду модулей; скрин viewport; экспорт FBX в `Content/` (или путь скилла).
3. Собрать второй модуль при необходимости (например technical bay) для разнообразия маршрута.
4. Смоделировать **консоль энергосети** (читаемые панели, место occupy).
5. Смоделировать **горелку** + **повреждённую панель** (и простой intact/repaired вид через материал или второй меш).
6. (Опц.) пульт реактора. Экспорт всех props FBX.

### Фаза B — Импорт и данные в Unreal (`user-unreal-mcp` + Editor)

7. Импортировать FBX; проверить масштаб/коллизии; создать/обновить **ModuleDefinition** для отсеков (скилл модулей / editor tool T02a).
8. Создать BP-обёртки устройств на C++-базах (когда базы готовы) с назначенными мешами: `BP_EnergyConsole`, `BP_DamagedPanel`, `BP_RepairTorch`.
9. Собрать карту `EngineerTraining`: стык модулей → отсек; PlayerStart; расстановка консоли, панели, стенда горелки; свет.

### Фаза C — Геймплей C++ (параллельно с A/B где можно)

10. Character + Interact; Workstation occupy/leave; Energy model + UI; Repair progress; Scenario director; автотесты моделей.
11. Меню: `Тренировки` → `Инженер` → OpenLevel карты из шага 9.

### Фаза D — Ситуации на уровне

12. Director: старт с разбалансом энергии + повреждённой панелью; objective на консоль → щиты; затем горелка → ремонт; success → меню.
13. (Опц.) бит перегрузки реактора.
14. Smoke 3×; обновить статус в backlog/доках.

